Chat-led Hybrid Application

AI reliance≈ 60% AI · 40% manual

Baseline. The form is housed inside the chat — the agent leads, you fill.

Overview

This prototype uses the existing widget function and takes the user to a “chat-led” hybrid application form.

Design reasoning

The aim was to focus on designing a version that prioritised a true AI hybrid experience. This involves adding more visibility to users on what is automated vs. what isn’t.

Pros

  • AI-first to encourage users to adopt new hybrid method.
  • Integrated form flow still feels familiar and gives customers agency to provide manual input — just housed in a chat-led function.
  • Menu progress tracker provides increased transparency and flexibility of how the user wants to complete the flow.
  • This hybrid chat can also be integrated and scaled into a returning customer journey application.

Cons

  • AI-first may turn away some users, especially the ones resistant to new technology adoption.
  • Flexible chat function may become confusing if the user overloads it with information — may need a reset / new chat function.

Sized to a 375 × 812 iPhone viewport inside the browser, with the safe-area spacing the production web build will use. Type is set in Figtree where Articulat CF isn’t installed locally.

Interconnected Hybrid to Manual Application

AI reliance≈ 60% AI · 40% manual

Same balance as V1, but the user picks which surface they answer on.

Overview

This prototype uses the existing widget function and takes the user to a similar hybrid chat function, however is also given the choice to toggle to the manual form. Both forms have slightly different features.

Design reasoning

The aim was to focus on designing a version that prioritised a true AI hybrid experience. This involves adding more visibility to users on what is automated vs. what isn’t, and providing them with options.

Pros

  • 2-mode feature provides users with choice — answers made in one mode are interchangeable with the other.
  • Can A/B test the modes and analyse user behaviour.
  • Other pros are similar to version 1.

Cons

  • Switching between the two modes plus a flexible hybrid chat may overload users — this may need more guardrails or educational moments implemented.

Document-led draft & approve

AI reliance≈ 75% AI · 25% manual

The customer answers one question and approves three documents. Broker Assist writes the rest.

Overview

This version flow follows HAILO’s flow similarly where the application is solely done by capturing documents. Details are pre-filled.

Pros

  • Shortest path to a complete application — approval is far cheaper than entry.
  • Confidence shading and an editable box per field keep the automation legible rather than magic.

Cons

  • Rubber-stamping risk: people may approve without reading, which is a compliance exposure.
  • Everything hinges on document quality — a bad scan turns a card amber and the trust with it.

Uploads, the bank connection and the code check are simulated on timers so each beat is visible. Screens follow Figma node 128-4865.

V5 · Section assist

AI reliance≈ 70% AI · 30% manual

The form stays the customer’s, but a document fills most of every section.

Overview

The widget opens a single guided journey: reason for the loan, loan preference, an SMS check, then the application itself, one section at a time. Assist is no longer attached to each question — there is one assistant per section, and it leads with document upload. The lender bar carries over from version 2: locked until the mobile is verified, then a dropdown of the shortlist that narrows once identity is checked.

The assist surface

One assistant per section, not one per question. A dock sits between the form and the Continue button. It never covers a field, it stays on screen while the section is filled in, and it says what it can do right now — “Fill this section from a photo”. It flashes lightly in every new section until it has been opened. Tapping it raises a sheet over the lower half of the screen; the form stays visible behind it.

After the document is read

A document rarely covers a whole section, so whatever it missed turns red and marked Still needed, and the screen scrolls to the first one. The dock stops selling the upload and becomes Broker Assist — get help with this section, so the next move is always obvious.

Pros

  • Upload is the headline action, so the assistant reads as a shortcut rather than a chatbot.
  • Persistent but passive — always in view, never in the way of the fields.
  • The dock’s copy changes as the section fills, so it keeps earning attention.
  • The customer is never left guessing what is still outstanding after a document is read.
  • Answers return as small labelled cards, not a message log, so nothing feels like a support queue.

Cons

  • Costs ~60px of vertical space on every section screen.
  • A bottom sheet on a tall section means the customer loses sight of the fields being filled.

Only Personal is live on the widget. Upload, scanning and verification are simulated — every document fills the section it belongs to.

V6 · Manual form, Broker assist dock

AI reliance≈ 35% AI · 65% manual

The form is the product; Broker assist sits above Continue and can be ignored.

Overview

Starts on the same loanoptions.ai widget as versions 1 and 2, with the personal loan the only live tile. Loan use, then preferences, then the SMS check — which turns the locked Unlock lenders soon chip into the working 23 lenders dropdown from Version 2. From there it’s an ordinary form with the assist dock parked directly above the Continue button.

How it works

  • The dock carries an unread badge counting the four prompts, with the same four as bubbles on a rail above it — drag sideways for the rest, flick one down or off the end to be rid of it.
  • Opening it gives four standing prompts: fill from licence, view lender options, view loan rates, fast-track.
  • Either lender prompt opens the 23-lender bar; fast-track walks the three documents one at a time, each with its own upload button.
  • Anything the assistant fills is written into the visible form, never into a hidden state.

Pros

  • Lowest adoption risk of the assisted options — nothing changes if you never open it.
  • Easy to A/B: the same form with the dock on or off.
  • Chat is still available in full for customers who want it.

Cons

  • Most customers will never open it, so the AI value has to come from the bubbles.
  • Badly timed bubbles read as interruption; this needs real tuning.
  • Two surfaces to maintain for one flow.
